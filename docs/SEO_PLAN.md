# SEO Plan

**Situation:** the legacy site is a 27-URL WordPress install last updated in September 2020, with thin content, product-led URLs and no email capture. Whatever authority the domain holds sits mostly on the homepage and a handful of solution slugs.

**Objective:** carry every scrap of existing equity across, then compete on solution and industry intent instead of manufacturer names.

**Primary risk:** the many-to-one consolidation of nine legacy URLs into `/solutions/meeting-and-collaboration-spaces`, plus a sitewide trailing-slash change. Both are handled in REDIRECT_PLAN.md; both must be verified before cutover.

## 2. Metadata

Generated by a typed helper, never hand-written per page:

```ts
buildMetadata({ title, description, path, ogImage, type, noindex? }): Metadata
```

| Field | Rule |
|---|---|
| `<title>` | ≤60 characters. Pattern: `{Page} | SAAN` — home: `SAAN — AV, Digital Signage and Meeting Room Solutions | Bangalore`. Unique sitewide, checked at build. |
| `description` | 120–155 characters. Unique. Written for a human, includes the primary intent. |
| `canonical` | Absolute, self-referencing |
| Open Graph | `og:title`, `og:description`, `og:url`, `og:image` (1200×630), `og:type`, `og:locale=en_IN`, `og:site_name` |
| Twitter | `summary_large_image` |
| Robots | `index, follow` by default; `noindex` on anything containing a `[CONTENT REQUIRED]` marker or `status: 'placeholder'` |

**Build-time validation** (`npm run validate:seo`) fails the build on: a missing or duplicate title, a missing description, a description outside 120–155 characters, a title over 60 characters, a missing canonical, a missing OG image, more than one H1, or a skipped heading level.

This is the "content validation so important SEO fields cannot accidentally be omitted" requirement — it is a build gate, not a checklist.

## 4. URL principles

Lowercase, hyphenated, descriptive, no trailing slash, no dates, no IDs, no acronyms. `/solutions/room-automation-and-control` rather than the legacy `/automation/`. Slugs validated against `/^[a-z0-9]+(?:-[a-z0-9]+)*$/` with collision detection at build time.

## 5. Structured data (JSON-LD)

Emitted by typed builders in `src/components/seo/`, validated against the schema at build.

| Type | Where | Notes |
|---|---|---|
| `Organization` | Root layout | Legal name, logo, address, phones (with `contactType`), `sameAs` social URLs, `foundingDate` — **only fields verified in CONTENT_TODO §2** |
| `LocalBusiness` | `/contact`, root | `PostalAddress`, `geo`, `areaServed`, `openingHours`. **Omitted entirely until hours and coordinates are confirmed** — partial LocalBusiness data is worse than none. |
| `WebSite` | Root | `name`, `url`, `inLanguage: en-IN` |
| `BreadcrumbList` | Every page except `/` | Mirrors the visible breadcrumb exactly |
| `Service` | Each `/services/*` | `provider`, `serviceType`, `areaServed` |
| `FAQPage` | Solution, industry, service pages | **Only for FAQs visibly rendered on the page.** Never hidden, never generated. |
| `Article` | `/resources/[slug]` | `headline`, `author`, `dateModified`, `image` |
| `CreativeWork` | `/projects/[slug]` | Used in preference to a fabricated `Review`. Customer named only when permission is granted; otherwise the anonymous label. |
| `ImageObject` | Project galleries | Where captions add value |

**Prohibited:** `AggregateRating` and `Review` — SAAN has no verified review corpus, and inventing one is both a policy violation and a manual-action risk. `Product` markup is also excluded, since the site deliberately does not sell model numbers.

## 6. Sitemap and robots

`src/app/sitemap.ts` generates from the content graph. Excluded automatically: `noindex` pages, `status: 'placeholder'` projects, unverified partners, anything containing a `[CONTENT REQUIRED]` marker, `/privacy`, `/terms`.

Priorities: `/` 1.0 · solution and industry pages 0.9 · `/projects` and services 0.8 · project and partner detail 0.7 · resources 0.6 · about, contact, support 0.5.

`lastModified` comes from real content-change timestamps. It is never faked to "now" on every build — that trains crawlers to ignore it.

`robots.ts`: allow all, one `Sitemap:` directive, disallow `/api/`. **Staging emits `Disallow: /` plus `X-Robots-Tag: noindex` at the edge, driven by an environment variable** — an indexed staging site is the classic way to lose a launch.

---

## 7. Internal linking

Reverse links are derived from the content graph (INFORMATION_ARCHITECTURE §5), so link density is structural rather than manual. Minimum three contextual internal links per page, validated by test. Descriptive anchor text — never "click here", never a bare URL. Every solution links to at least two services, two industries and any related projects. No orphan pages: the link test asserts every published URL is reachable from `/` within three clicks.

## 8. Migration verification

Ordered gate before any DNS change:

1. Export Search Console top pages, queries and backlinks for the last 12 months (CONTENT_TODO 9.1).
2. Reconcile that export against CURRENT_URL_INVENTORY.md — WordPress sites routinely have indexed URLs absent from `wp-sitemap.xml` (attachment pages, tag archives, Elementor library entries).
3. Add any newly discovered URL to the redirect map.
4. Run the redirect test suite against staging: every legacy URL → single 301 → 200. No chains, no loops.
5. Crawl staging (Screaming Frog or equivalent): zero 404s, zero broken internal links, zero duplicate titles or descriptions, zero missing `alt`, one H1 per page.
6. Validate every JSON-LD block in the Rich Results Test.
7. Confirm the staging sitemap contains only intended URLs.

---

## 9. Launch and post-launch

**At launch:** verify the property in Search Console for the new host · submit `/sitemap.xml` · request indexing for the homepage and all eight solution pages · confirm `robots.txt` is *not* blocking (the single most common launch error) · verify the canonical host resolves and the other host 301s.

**Days 1–14:** Coverage report daily; any 404 spike triaged within 24 hours. Watch specifically for legacy URLs missing from the redirect map.

**Days 14–90:** track index coverage of all 31 fixed pages; monitor rankings for the intents in §3; confirm the nine-to-one consolidation recovers impressions on `/solutions/meeting-and-collaboration-spaces`. **A temporary ranking dip in the first 2–6 weeks is normal on a migration of this scale** — the site structure changed fundamentally, not just its design. Judge recovery at 90 days, not at 14.

**Rollback trigger:** if organic traffic falls more than 40% against the pre-launch baseline and is still down at day 21, execute ROLLBACK_PLAN.md while the cause is diagnosed.

---

## 10. Content SEO principles

Every page earns its ranking by answering a real question better than the alternatives. No doorway pages, no city-multiplied landing pages, no keyword-stuffed footers, no hidden text, and no FAQ markup for questions nobody asked. The comparison modules (`/resources`) are the strongest organic asset in the plan — "projector vs professional display", "LCD video wall vs direct-view LED", "consumer TV vs commercial display" are high-intent, genuinely useful, and almost nobody in the Indian market answers them honestly.
